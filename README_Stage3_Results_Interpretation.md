## 指标含义

### 1. Mean F1 (LCL) - 事件定位 F1 分数
**你的分数: 0.433 (43.3%)**

- **含义**: 衡量模型是否能正确检测到事件发生的位置（在 ±delta 帧内）
- **计算**: 基于 True Positive, False Positive, False Negative
- **解读**: 
  - ✅ **0.433 属于中等水平**
  - 说明模型能够检测到约 43% 的事件位置
  - 这是三个 F1 分数中最高的，说明事件定位相对较好

### 2. Mean F1 (event) - 事件级别 F1 分数
**你的分数: 0.110 (11.0%)**

- **含义**: 衡量完整事件序列的匹配准确度
- **计算**: 基于完整事件序列的匹配（包括事件类型和顺序）
- **解读**: 
  - ⚠️ **0.110 很低**
  - 说明模型在预测完整事件序列时准确度很低
  - 从你的序列对比可以看出：
    - 预测: `far_serve->far_serve->far_return_fh_gs->...` (10个事件)
    - 真实: `far_serve->near_return_bh_gs->far_stroke_fh_gs->...` (8个事件)
    - 模型预测了太多重复事件（如 `far_serve->far_serve`）

### 3. Mean F1 (element) - 元素级别 F1 分数
**你的分数: 0.180 (18.0%)**

- **含义**: 衡量细粒度动作元素的识别准确度（如 serve, return, stroke, fh, bh 等）
- **计算**: 基于每个动作元素的分类准确度
- **解读**: 
  - ⚠️ **0.180 较低**
  - 说明模型在识别细粒度动作元素时准确度不够
  - 例如：模型可能混淆了 `fh` 和 `bh`，或者 `gs` 和 `slice`

### 4. Edit Score - 编辑距离分数
**你的分数: 40.23 (最终最佳: 49.21)**

- **含义**: 基于 Levenshtein 距离，衡量预测序列和真实序列的相似度
- **范围**: 0-100（100 是满分，表示完全匹配）
- **计算**: 归一化的编辑距离，分数越高越好
- **解读**: 
  - ⚠️ **40-49 属于中等偏低**
  - 说明预测序列和真实序列的相似度约为 40-50%
  - 最佳 epoch (490) 达到了 49.21，说明训练过程中有改进

## 结果分析

### 优点 ✅
1. **事件定位相对较好** (F1 LCL: 0.433)
   - 模型能够检测到事件发生的大致位置
   - 这是后续改进的基础

2. **训练有改进**
   - 最佳 epoch (490) 的 Edit score (49.21) 比最终 (40.23) 更好
   - 说明模型在训练过程中学到了有用的特征

### 问题 ⚠️
1. **过预测（Over-prediction）**
   - 预测了 10 个事件，真实只有 8 个
   - 存在重复预测（如 `far_serve->far_serve`）
   - 说明模型对事件边界的判断不够准确

2. **事件分类错误**
   - 预测: `far_return_fh_gs` vs 真实: `near_return_bh_gs`
   - 混淆了 `far/near`、`fh/bh` 等细粒度特征
   - 说明模型对动作细节的识别能力不足

3. **事件序列匹配度低** (F1 event: 0.110)
   - 完整事件序列的准确度很低
   - 说明模型在理解事件顺序和类型方面还有很大改进空间

## 改进建议

### 1. 数据相关
- **增加训练数据**: 如果手动验证数据较少，考虑增加更多标注
- **数据质量**: 确保标注的一致性和准确性
- **数据平衡**: 检查各类事件的分布是否平衡

### 2. 模型训练
- **调整学习率**: 尝试更小的学习率（如 0.00005）进行更精细的微调
- **增加训练轮数**: 当前训练到 490 epoch，可以尝试更多轮数
- **早停策略**: 基于验证集的 Edit score 进行早停，避免过拟合

### 3. 后处理
- **NMS 窗口**: 调整 NMS 窗口大小，减少重复预测
- **阈值调整**: 调整事件检测的阈值，减少过预测
- **序列平滑**: 对预测序列进行平滑处理，去除明显错误的重复

### 4. 模型架构
- **特征融合**: 确保 RGB 和 optical flow 特征的有效融合
- **时序建模**: 改进时序建模能力，更好地理解事件顺序
